# Nightly security sweep, 2026-09-17

No `docs/security/sweeps/` folder existed before this run, so this is the
first nightly sweep. Baseline for "new" is the last 24 hours, which is
almost entirely the 2026-09-16 security review (`docs/SECURITY.md`,
`docs/security/2026-09-16-*.md`) plus the bug-bash commits before it.

## Checked

**1. `npm audit`.** Root tree and `backend/`, each with and without
`--omit=dev`: all four runs came back "found 0 vulnerabilities." No
advisory, so nothing to patch or bump.

**2. Secret scan.** Scanned every commit since the baseline (`337fc38a`
through `7d49ebab`, 50 commits) via `git log -p`, plus the full working
tree including `public/`, `docs/`, `backend/data/`, fixtures and
`.github/`. Nothing live-looking found. One item worth a glance but not a
rotation: a scraped operator's own presigned S3 URL (`AKIA...` access key
ID inside an `X-Amz-Credential` query param) sitting in
`public/o/o-culinarybackstreets-com.json` and `backend/data/photos/`,
carried over from crawling that operator's own photo CDN on 2026-09-14.
It is culinarybackstreets.com's vendor's key, not Outset's, and the
matching signature was scoped to a 300-second window that has long since
expired. Everything else that matched a secret shape (bare prefixes named
in `docs/SECURITY.md`/`GO-LIVE.md`/the review reports, a redacted test
fixture, `.env.example` with blank values, localStorage key names, a
public reCAPTCHA site key) was documentation or a placeholder, not a real
credential. No `.env` file exists in the repo.

**3. Third-party host drift.** Compared `index.html`, a fresh `npx vite
build` output, and `src/` against the allowed set in
`docs/security/2026-09-16-rendering.md` (fonts stylesheet, `wsrv.nl`,
the API, the Photon geocoder, the YouTube/Vimeo embed hosts, Stripe
checkout). Found one real gap: the most recent commit
(`7d49ebab1`, "Pay inside the listing: Stripe's embedded checkout
replaces the redirect") added `src/components/booking/EmbeddedCheckout.tsx`,
which injects `<script src="https://js.stripe.com/v3/">` and mounts
Stripe's card form in a Stripe-hosted frame — but the CSP meta tag was
never updated for it. `script-src` was still `'self'`, so any browser
enforcing the policy would have blocked Stripe.js outright and broken
payments, not just left a gap. **Fixed**, see below. All the other hosts
seen in the built bundle (`axethrowingtampa.com`, `bigredballoon.com`,
etc.) are operator website URLs baked into fixture/seed data as plain
strings for "visit their site" links, not script/connect/frame
destinations, so they don't need a CSP entry.

**4. Hacked-page screen.** Wrote a script under `/tmp` that imports
`isCompromisedText`, `isCompromisedPhrase` and `FOREIGN_SCRIPT_RUN` from
`backend/src/sync/contacts.ts` unchanged, and ran them over every string
field of `public/catalog.json`'s 59,163 operators and all 59,162 files in
`public/o/`. Results:

- `public/catalog.json` (the browse-page summary, fewer fields per
  operator): **13 flagged**, every one because the operator's `cover`
  photo URL is itself a gambling-spam banner image
  (`togel-hongkong.cc`, `slotgacor.webp`, `bandar-togel-online.png`, and
  so on) — meaning a spam banner is the actual photo a guest sees on that
  listing's card today.
- `public/o/*.json` (the full per-listing detail file, served live under
  `/o/<id>.json` and copied into `dist/` on build, so it ships to GitHub
  Pages): **106 flagged**, all 13 of the above plus 93 more where a
  paragraph of Indonesian gambling/lottery spam (`slot gacor`, `togel`,
  `RTP`, `bandar`, `maxwin`, `judi online`, and so on) sits inside a
  `blurb`, `desc` or offering field.

  This is not a gap in the regex — `SPAM_LINE` and friends caught every
  one of these correctly, which is how the scan found them. It's that the
  quarantine logic in `toCatalogItem` (added in the 2026-09-16 review,
  commit `63ff9b3f9`) only withholds spam a *future* crawl would add; its
  own comment says as much ("only what this sync would have published
  from the crawl is withheld"). It does nothing for spam that was already
  written into the `facts`/`offerings` tables by a hacked page before that
  fix existed, and these 106 are exactly that: already-synced rows from
  before the fix, still being published on every sync since. Since there
  is no prior sweep, all 106 are "new" by definition; see Needs Harshil —
  this needs a database cleanup this environment cannot make.

  One false positive worth a look, not a fix tonight:
  `public/o/o-easttnscouts-org.json`'s "Campsite Details" offering repeats
  "LIVE CLASS SCHEDULE, Week 1/2/3/4" enough times to trip
  `isKeywordStuffed`'s stuffing ratio. It's a real Scout camp's class
  schedule, not spam. No new spam phrase was needed tonight since nothing
  got past `SPAM_LINE`/`HACKED_SCRIPT_SPAM`/`hasRepeatedSuspectWord` —
  the miss this sweep found runs the other way (a false flag, not a
  missed phrase), so it wasn't added as a "spam phrase … with a test."

**5. Live checks — could not run.** This sandbox's own outbound proxy
returned `403 CONNECT tunnel failed` for both `https://onoutset.com/` and
`https://outset-api.onrender.com/health`, before any request reached
either host — the same kind of sandbox-egress block the 2026-09-16
rendering review hit against `wsrv.nl` and `bigwhite.com`. CSP/referrer
meta tags, API security headers, the `/health` payload and the CORS
answer against `https://evil.example` were not verified tonight. Needs
either a run from an environment with open egress to those two hosts, or
a human to spot-check the headers.

**6. `.github/workflows`.** Only `.github/workflows/e2e.yml` exists now —
the 24-hour window's `88355dfd1` deleted the 7 crawl/photo/payout/backup
workflows because GitHub disabled Actions on the account for scraping
third-party sites, and those jobs now run on Render cron/workers per
`render.yaml`. Every `uses:` line in what's left is pinned to a full
commit SHA (`actions/checkout`, `actions/setup-node`,
`actions/upload-artifact`, each with a version comment). Top-level
`permissions: contents: read`, no per-job widening, and the single job
never pushes. Nothing unpinned, nothing over-scoped, no unexplained new
workflow.

**7. New dependencies.** One commit (`337fc38ae`) in the window is where
both `package.json` files first appear in this checkout, so "new since
baseline" is everything in them. Root: `@neon/config` and `@neon/env`
(verified against the npm registry: Apache-2.0, maintained by
`neonteam`/Neon's own GitHub org, "Config-as-Code for Neon" — matches
`neon.ts` at the repo root and the Neon Postgres host `DATABASE_URL`
already documented in `docs/SECURITY.md`), plus `react`, `react-dom` and
their dev tooling. Backend: `@anthropic-ai/sdk`, `@hono/node-server`,
`cheerio`, `hono`, `nodemailer`, `openai`, `pg`, `zod`, and dev-only
`playwright`/`tsx`/`typescript`/`@types/*`. Checked every one of these
for an `install`/`preinstall`/`postinstall` lifecycle script, in the
installed `package.json` and via `npm view <pkg> scripts`: none has one.
