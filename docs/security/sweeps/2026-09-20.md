## Fixed

**A hacked operator page could run its own script on our static pages**
(`e11894038`). This window's new landing and
listing page generators (`backend/src/sync/pages.ts`,
`backend/src/sync/listingPages.ts`) embed each business's title and FAQ
text, read straight off its own site, inside a `<script
type="application/ld+json">` tag via `JSON.stringify`, which never escapes
`<`. A business name crawled off a hacked page containing
`</script><script>...</script>` would close that tag early and let the rest
parse as real HTML, on a static page GitHub Pages serves with no CSP of its
own. Escaped `<` to `<` before embedding in both files (`e11894038`) and
added a regression test to each proving a title carrying that sequence
cannot break out of the tag. New since the baseline (this window's SEO
work), and exactly the shape of bug this sweep exists to catch, so fixed
here rather than left for a report.

**The concierge's own standalone type-check failed** (`183a54975`).
`backend/src/concierge/plan.ts:236` spread an `unknown[]` into a prepared
statement's `.all()`, which `node:sqlite`'s types reject (`TS2345`). `npm
test` itself still passed 330/330, since the test loader does not run a
full project type-check, but `npx tsc -p backend/tsconfig.json
--allowImportingTsExtensions` failed outright. New since the baseline (this
window's concierge feature). Every value actually pushed onto `args` is a
string or a number, so typing it `(string | number)[]` was enough; no
behavior change.

Both fixes verified against the full baseline before pushing: root `npx tsc
-b` clean; root `npm test` 476/476; backend `npm test` 330/330 (including
the two new regression tests); backend `npx tsc -p tsconfig.json
--allowImportingTsExtensions` clean (this also cleared last night's
`metrics.test.ts` `TS2352`, which the team had already fixed in `861963d99`
earlier this window); `npx vite build` succeeds. Pushed as two commits,
`e11894038` then `183a54975`, straight to `main`.
