**Found and fixed.**

- **One bad menu in a shop's saved record answered 500 to every booking** (`8eb6a7aaf`). The dashboard record is
  stored as the device sends it, so `options` and `addons` can be any shape at all. `POST /bookings` decided
  whether a shop had a menu by that field's length, and a string has a length, so a menu of `"oops"` got as far
  as `priceBooking`, which called `.filter` on it. Every booking for that shop answered 500: the guest saw
  "Something went wrong", the operator never heard about the request, and it stayed that way until somebody
  fixed the row by hand. Reproduced against the local Postgres, four shapes tried, one of them a 500 and two
  more quietly wrong. Both fields are read through one helper now that treats anything but an array as an empty
  menu, on the operator's patch and on the crawled listing file alike, so a malformed record costs the shop its
  prices, which already means pay on site, rather than its bookings. Two store-e2e checks cover it.
- **A shop that hid its listing was still taking bookings in the phone app** (`7618a258e`). The dashboard has two
  switches that stop bookings: Published off takes the page off the site, Accepting off leaves it listed and
  turns bookings away. The desktop listing page has read both since they were built. The listing in the phone
  frame, which is the same page a shared link, a booking email, Trips or a wishlist opens, read neither, so a
  guest whose link still worked got the whole picker: they chose a service, a date, a start time and a party,
  typed their name, mobile and email, pressed Request to book, and only then got a toast reading "This listing
  is hidden right now", with the booking refused and nothing to do next. Both flags reach a guest through the
  operator's published patch (`loadListing` calls `setOperatorOverride` with them), so this is every guest, not
  only the operator's own browser. The phone listing reads the same pair now and says which of the two it is;
  the bar at the bottom offers "Find another" in place of Reserve. One predicate, `bookingPaused`, so a third
  surface cannot pick up only one of the flags. Five tests.
- **Two NUL bytes made the store test file binary to git and grep** (`4e5fa3b18`). `scripts/store-e2e.mts` checks
  that a booking code with a NUL byte in it answers 404 rather than 500, and wrote that byte as a literal NUL
  inside `encodeURIComponent("...")`. Both tools read a NUL as the mark of a binary file, so the script was
  invisible to a search and every diff of it read "Binary files differ", on the one file a reviewer most wants
  to read on a change to the booking routes. Written as the `\0` escape, which is the same string at runtime.
